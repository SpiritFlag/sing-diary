# CLAUDE.md

## 환경 제약 (다른 모든 판단보다 우선)

이 서버는 AWS Lightsail, **RAM 1.9GB**다. 무거운 프로세스 하나면 스왑으로 밀려나
시스템 전체가 멈춘다. "확인차 한 번만 돌려보자"는 판단 자체를 하지 마라.

## 로컬 실행 금지 명령

아래 명령은 어떤 이유로도 로컬에서 실행하지 않는다. 검증이 필요하면 반드시
"검증 절차" 섹션의 방법으로 대체한다.

- `next build` / `npm run build` — 금지. 빌드는 Vercel이 한다.
- `tsc --noEmit` / `npm run typecheck` — 금지. Vercel의 `next build`에 타입체크가 포함된다.
- `eslint` / `npm run lint` — 금지. 위와 동일하게 빌드에 포함된다.
- `vitest` watch 모드 — 금지. 항상 `vitest run`(= `npm test`)만.
- `next dev` — 사용자가 명시적으로 요청한 경우에만 실행하고, 용건이 끝나면
  종료했는지 확인한다. 켜둔 채 방치하지 않는다.

## 검증 절차 (빌드·타입·린트)

1. 변경을 커밋하고 **develop 브랜치로 푸시**한다.
2. Vercel이 preview 빌드를 실행한다. 이 빌드가 lint + 타입체크를 포함한다
   (빌드 로그의 "Linting and checking validity of types" 단계).
3. 결과는 Vercel 빌드 로그로 확인한다. 로그를 직접 조회할 수 없으면
   사용자에게 확인을 요청한다.

타입 에러가 의심돼도 로컬에서 tsc를 돌려 확인하지 말고, 코드를 읽어서 판단하거나
푸시 후 빌드 로그로 확인한다.

## 테스트 (유일한 로컬 검증 수단)

- Vercel은 테스트를 실행하지 않는다. vitest만 로컬에서 돌린다.
- 테스트 다수가 실제 Neon 테스트 브랜치(`TEST_DATABASE_URL`)에 접속하는
  통합 테스트라서 로컬 실행이 유일한 검증 수단이다.
- **기본은 스코프 실행**: 변경과 관련된 파일만 지정해서 돌린다.
  ```bash
  npm test -- tests/<관련파일>.test.ts
  ```
- 전체 실행(`npm test`)은 최종 확인 등 꼭 필요할 때만, 다른 무거운 프로세스가
  없는 상태에서 한 번만 돌린다.
- `vitest.config.ts`의 `maxWorkers: 1`은 메모리 제약 때문이다. 제거하지 마라.

## 일반 수칙

- 무거운 프로세스(테스트, npm install 등)는 **한 번에 하나만**. 병렬 실행 금지.
- `npm install`은 의존성이 실제로 바뀌었을 때만.
- 작업을 마치기 전, 백그라운드에 남겨둔 프로세스가 없는지 확인한다.
